I have been running Google Photos and Synology Photos in parallel for years. Every photo from my phone backed up to both. Every memory in two places I don't fully control.

This year I started pulling the big tech plug, one service at a time. Google Photos is the first domino.

This is part one of what will be an ongoing series about degoogling. Not a manifesto — just notes from actually doing it.

---

## The inventory

184.28 GB. 19 Takeout archive files. That's how much of my life Google has been holding.

Before I even touched the migration, I did two things:

1. Disabled backup and sync in the Google Photos app
2. Uninstalled the app entirely

Hello, standard Apple Photos (without iCloud sync — that's a different rabbit hole).

The Takeout export was already running. Downloading 19 ZIP files through Dropbox while I figured out the rest of the plan.

---

## Why rsync from Google doesn't work

My first instinct was to treat Google Photos like a remote filesystem and rsync the originals out. Clean, incremental, scriptable.

That's not possible anymore.

Google killed the full-library readonly API access path in 2025. The current Photos API surface is the Picker API, which only works with user-selected items — not with "give me everything in the library." There's no "mount Google Photos and pull originals" option that actually works for this use case.

Takeout is the only viable full-library export. Google's own Synology migration documentation points you there.

---

## The Takeout problem

Takeout exports come with a catch: metadata isn't embedded in the files.

Instead, Google ships a sidecar `.json` file for each photo — sometimes named `photo.jpg.json`, sometimes `photo.jpg.supplemental-meta.json` since they changed the format. The JSON contains things like `photoTakenTime.timestamp`, geolocation, and description.

If you don't process those sidecars before importing, your 2017 holiday photos show up with today's date in Synology Photos. The timeline view becomes useless.

---

## The plan

After thinking it through, the right sequence is:

1. **Export from Google** via Takeout — Photos only, 50 GB max per archive to reduce the chance of corrupt downloads
2. **Download the archives** — in my case via Dropbox as intermediary, then synced to a local working directory
3. **Extract in place** — treat the source directory as disposable; extract archives into it, delete the archive on success
4. **Apply sidecar timestamps** — use `exiftool` to read the JSON sidecar timestamps and write them into the EXIF/QuickTime date fields of each media file
5. **Deduplicate** — exact content hash comparison against the existing Synology corpus
6. **Import survivors** into `TARGET_DIR/takeout/YYYY/MM/filename`
7. **Let Synology index** — the DS1522+ can handle it without babysitting
8. **Verify, then clean up** — only delete the source set after spot-checking timestamps, formats, and counts

The key insight: `TARGET_DIR/takeout/` is an intentional quarantine. If anything goes wrong, one `rm -rf /volume1/photo/takeout` and the whole import attempt is gone. The existing library is untouched.

---

## The deduplication problem

Years of parallel running means guaranteed duplicates. My phone backed up to both services simultaneously. Some photos exist in the Synology corpus already — probably at different paths, with different filenames, potentially with slightly different metadata depending on which app processed them.

Deduplication needs to be exact content hash comparison, not filename or date matching. Both are unreliable across two ecosystems.

The strategy:

- **Pass 1 — exact duplicates**: SHA-256 hash every file. If the same bytes exist anywhere in the existing Synology tree, skip it. This is safe to automate.
- **Pass 2 — visual near-duplicates**: After exact dedupe, use something like Czkawka to flag visually similar images — same photo at different compression, burst shots, WhatsApp-compressed copies. This pass needs human review, not blind deletion.

The script I wrote only does pass 1. Pass 2 is a separate problem.

## The script

I wrote a bash script that handles the whole import pipeline. Two arguments: `SOURCE_DIR` and `TARGET_DIR`.

Install the dependencies on macOS:

```bash
brew install exiftool
```

Basic usage:

```bash
chmod +x ./gphotos_to_synology_takeout_upsert.sh
./gphotos_to_synology_takeout_upsert.sh "/my/takeout/dir" "/volume1/photo"
```

Dry run first — highly recommended before touching a 184 GB library:

```bash
./gphotos_to_synology_takeout_upsert.sh "/my/takeout/dir" "/volume1/photo" --dry-run --keep-workdir
```

What it does, in order:

**Step 1 — Extract archives in place.** Scans `SOURCE_DIR` for `.zip`, `.tgz`, `.tar.gz`, and `.tar` files. Extracts each one directly into `SOURCE_DIR`. Deletes the archive only if extraction succeeded and new files appeared — if extraction fails or produces nothing, the archive stays. This makes reruns safe: already-extracted content is just processed again, failed archives stay for investigation.

**Step 2 — Apply sidecar timestamps.** Walks every `.json` and `.supplemental-meta.json` file in the source tree. Finds the matching media file (by filename, with fallback sibling matching). Reads `photoTakenTime.timestamp` from the JSON and calls `os.utime()` to set the file modification time. Handles both old and new Takeout sidecar naming conventions.

**Step 3 — Write EXIF/QuickTime date fields.** Calls `exiftool` to copy the corrected file modification time into `DateTimeOriginal`, `CreateDate`, `ModifyDate`, and the QuickTime equivalents for video files. This is what makes Synology Photos' timeline view actually work.

**Step 4 — Collapse internal duplicates.** SHA-256 hashes every media file in the incoming set. Keeps only the first occurrence of each hash. If you've downloaded the same Takeout export twice, this handles it.

**Step 5 — Hash the existing target tree.** Recursively walks `TARGET_DIR` and builds a hash index of every existing media file. This is the slow step on a large library — the DS1522+ will take a while on 184 GB, but it only runs once per import attempt.

**Step 6 — Build the import plan.** For each unique incoming file not already in the target, asks `exiftool` for the corrected date and computes the destination path: `TARGET_DIR/takeout/YYYY/MM/filename`. Files with no sane date fall back to `TARGET_DIR/takeout/undated/`.

**Step 7 — Copy survivors.** Copies only new files into the target. If two different files want the same destination filename, appends `__dup1`, `__dup2`, etc. rather than silently overwriting.

The full script is below.

#!/usr/bin/env bash
set -Eeuo pipefail

usage() {
  cat <<'USAGE'
Usage:
  gphotos_to_synology_takeout_upsert_v2.sh SOURCE_DIR TARGET_DIR [options]

What it does:
  - treats SOURCE_DIR as a temp-ish working area
  - scans SOURCE_DIR for Google Takeout archives and extracts them IN PLACE
  - deletes each archive only after successful extraction with new files appearing
  - applies Google Takeout sidecar timestamps to file mtimes in SOURCE_DIR
  - writes common EXIF/QuickTime date fields from corrected file mtimes via exiftool
  - removes exact duplicates within SOURCE_DIR logically during import planning
  - scans TARGET_DIR recursively for exact duplicates by content hash
  - copies only new files into TARGET_DIR/<subdir>/
  - places files under YYYY/MM when a sane corrected timestamp exists
  - otherwise falls back to TARGET_DIR/<subdir>/undated/

Arguments:
  SOURCE_DIR   Path containing Takeout zips/tarballs and/or already extracted files
  TARGET_DIR   Existing Synology Photos root, e.g. /volume1/photo

Options:
  --subdir NAME        Destination subdir inside TARGET_DIR (default: takeout)
  --keep-workdir       Keep temp workdir after success/failure
  --no-organize        Do not use YYYY/MM; keep relative paths under <subdir>/raw/
  --dry-run            Do everything except final copy into TARGET_DIR
  -h, --help           Show help

Examples:
  ./gphotos_to_synology_takeout_upsert_v2.sh "/my/takeout/dir" "/volume1/photo"
  ./gphotos_to_synology_takeout_upsert_v2.sh "/my/takeout/dir" "/volume1/photo" --dry-run
USAGE
}

log() {
  printf '[%s] %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$*"
}

warn() {
  printf '[%s] WARN: %s\n' "$(date '+%Y-%m-%d %H:%M:%S')" "$*" >&2
}

die() {
  printf 'ERROR: %s\n' "$*" >&2
  exit 1
}

command -v python3 >/dev/null 2>&1 || die "python3 is required"
command -v exiftool >/dev/null 2>&1 || die "exiftool is required. On macOS: brew install exiftool"

SOURCE_DIR="${1:-}"
TARGET_DIR="${2:-}"
[[ -n "$SOURCE_DIR" && -n "$TARGET_DIR" ]] || { usage; exit 1; }
shift 2 || true

SUBDIR="takeout"
KEEP_WORKDIR=0
ORGANIZE_BY_DATE=1
DRY_RUN=0

while [[ $# -gt 0 ]]; do
  case "$1" in
    --subdir)
      [[ $# -ge 2 ]] || die "--subdir requires a value"
      SUBDIR="$2"
      shift 2
      ;;
    --keep-workdir)
      KEEP_WORKDIR=1
      shift
      ;;
    --no-organize)
      ORGANIZE_BY_DATE=0
      shift
      ;;
    --dry-run)
      DRY_RUN=1
      shift
      ;;
    -h|--help)
      usage
      exit 0
      ;;
    *)
      die "Unknown option: $1"
      ;;
  esac
done

[[ -d "$SOURCE_DIR" ]] || die "SOURCE_DIR does not exist or is not a directory: $SOURCE_DIR"
[[ -d "$TARGET_DIR" ]] || die "TARGET_DIR does not exist or is not a directory: $TARGET_DIR"

SOURCE_DIR="$(cd "$SOURCE_DIR" && pwd)"
TARGET_DIR="$(cd "$TARGET_DIR" && pwd)"
DEST_ROOT="$TARGET_DIR/$SUBDIR"

WORKDIR="$(mktemp -d "${TMPDIR:-/tmp}/gphotos_takeout_upsert.XXXXXX")"
TARGET_INDEX="$WORKDIR/target_hashes.tsv"
INCOMING_INDEX="$WORKDIR/incoming_hashes.tsv"

cleanup() {
  if [[ $KEEP_WORKDIR -eq 1 ]]; then
    log "Keeping workdir: $WORKDIR"
  else
    rm -rf "$WORKDIR"
  fi
}

log "SOURCE_DIR = $SOURCE_DIR"
log "TARGET_DIR = $TARGET_DIR"
log "DEST_ROOT  = $DEST_ROOT"

extract_archives_in_source() {
  log "Scanning source for Takeout archives to extract in place"
  local extracted_any=0

  while IFS= read -r -d '' archive; do
    local lower before_count after_count ok=0
    lower="${archive,,}"
    before_count=$(find "$SOURCE_DIR" -type f | wc -l | tr -d ' ')

    log "Extracting in place: $archive"

    if [[ "$lower" == *.zip ]]; then
      if unzip -o -q "$archive" -d "$SOURCE_DIR"; then
        ok=1
      fi
    elif [[ "$lower" == *.tar.gz || "$lower" == *.tgz || "$lower" == *.tar || "$lower" == *.tar.bz2 || "$lower" == *.tbz2 || "$lower" == *.tar.xz || "$lower" == *.txz ]]; then
      if tar -xf "$archive" -C "$SOURCE_DIR"; then
        ok=1
      fi
    else
      warn "Skipping unsupported archive format: $archive"
      continue
    fi

    after_count=$(find "$SOURCE_DIR" -type f | wc -l | tr -d ' ')

    if [[ "$ok" -eq 1 && "$after_count" -gt "$before_count" ]]; then
      log "Extraction successful, deleting archive: $archive"
      rm -f "$archive"
      extracted_any=1
    elif [[ "$ok" -eq 1 ]]; then
      warn "Extractor returned success but no new files appeared. Keeping archive: $archive"
    else
      warn "Extraction failed. Keeping archive: $archive"
    fi
  done < <(find "$SOURCE_DIR" -type f \( -iname "*.zip" -o -iname "*.tgz" -o -iname "*.tar.gz" -o -iname "*.tar" -o -iname "*.tbz2" -o -iname "*.tar.bz2" -o -iname "*.txz" -o -iname "*.tar.xz" \) -print0)

  if [[ "$extracted_any" -eq 1 ]]; then
    log "Finished extracting archives in source dir"
  else
    log "No archives extracted"
  fi
}

extract_archives_in_source

log "Applying Google Takeout sidecar timestamps to file mtimes in source dir"
python3 - "$SOURCE_DIR" <<'PY'
import json
import os
import sys
from pathlib import Path

root = Path(sys.argv[1])
media_exts = {
    '.jpg','.jpeg','.png','.heic','.heif','.webp','.gif','.tif','.tiff',
    '.mp4','.mov','.m4v','.avi','.mkv','.3gp','.webm',
    '.dng','.nef','.cr2','.cr3','.arw','.rw2','.orf'
}

applied = 0
failed = 0

for sidecar in root.rglob('*.json'):
    if not sidecar.is_file():
        continue

    name = sidecar.name
    candidates = []

    if name.endswith('.supplemental-meta.json'):
        base = name[:-len('.supplemental-meta.json')]
        candidates.append(sidecar.with_name(base))
    elif name.endswith('.json'):
        base = name[:-len('.json')]
        candidates.append(sidecar.with_name(base))

    sibling_files = [p for p in sidecar.parent.iterdir() if p.is_file() and p.suffix.lower() in media_exts]
    target = None
    for c in candidates:
        if c.exists() and c.is_file():
            target = c
            break

    if target is None:
        base_no_suffix = candidates[0].name if candidates else None
        if base_no_suffix:
            for s in sibling_files:
                if s.name.startswith(base_no_suffix):
                    target = s
                    break

    if target is None:
        continue

    try:
        data = json.loads(sidecar.read_text(encoding='utf-8'))
    except Exception:
        failed += 1
        continue

    ts = None
    for path in [
        ('photoTakenTime', 'timestamp'),
        ('creationTime', 'timestamp'),
        ('modificationTime', 'timestamp'),
    ]:
        cur = data
        ok = True
        for key in path:
            if isinstance(cur, dict) and key in cur:
                cur = cur[key]
            else:
                ok = False
                break
        if ok:
            try:
                ts = int(str(cur))
                break
            except Exception:
                pass

    if ts is None or ts <= 0:
        continue

    try:
        os.utime(target, (ts, ts))
        applied += 1
    except Exception:
        failed += 1

print(f"applied={applied} failed={failed}")
PY

log "Writing common metadata fields from corrected file mtimes with exiftool"
find "$SOURCE_DIR" -type f \( \
  -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.png' -o -iname '*.heic' -o -iname '*.heif' -o -iname '*.webp' -o -iname '*.gif' -o -iname '*.tif' -o -iname '*.tiff' -o \
  -iname '*.dng' -o -iname '*.nef' -o -iname '*.cr2' -o -iname '*.cr3' -o -iname '*.arw' -o -iname '*.rw2' -o -iname '*.orf' \
\) -print0 | xargs -0 -I{} exiftool -overwrite_original -P \

\) -print0 | xargs -0 -I{} exiftool -overwrite_original -P -api QuickTimeUTC=1 \
  '-CreateDate<FileModifyDate' \
  '-ModifyDate<FileModifyDate' \
  '-MediaCreateDate<FileModifyDate' \

log "Indexing source media and collapsing exact duplicates within the source set"
python3 - "$SOURCE_DIR" "$INCOMING_INDEX" <<'PY'
import hashlib
import sys
from pathlib import Path

src = Path(sys.argv[1])
index_path = Path(sys.argv[2])
media_exts = {
    '.jpg','.jpeg','.png','.heic','.heif','.webp','.gif','.tif','.tiff',
    '.mp4','.mov','.m4v','.avi','.mkv','.3gp','.webm',
    '.dng','.nef','.cr2','.cr3','.arw','.rw2','.orf'
}

seen = {}
count = 0

def sha256_file(path: Path):
    h = hashlib.sha256()
    with path.open('rb') as f:
        for chunk in iter(lambda: f.read(1024 * 1024), b''):
            h.update(chunk)
    return h.hexdigest()

with index_path.open('w', encoding='utf-8') as out:
    for p in sorted(src.rglob('*')):
        if not p.is_file():
            continue
        if p.suffix.lower() not in media_exts:
            continue
        digest = sha256_file(p)
        if digest in seen:
            continue
        seen[digest] = str(p)
        out.write(f"{digest}\t{p}\n")
        count += 1

print(f"unique_incoming={count}")
PY

log "Indexing target tree recursively for exact duplicate detection"
python3 - "$TARGET_DIR" "$TARGET_INDEX" <<'PY'
import hashlib
import sys
from pathlib import Path

target = Path(sys.argv[1])
outfile = Path(sys.argv[2])
media_exts = {
    '.jpg','.jpeg','.png','.heic','.heif','.webp','.gif','.tif','.tiff',
    '.mp4','.mov','.m4v','.avi','.mkv','.3gp','.webm',
    '.dng','.nef','.cr2','.cr3','.arw','.rw2','.orf'
}

def sha256_file(path: Path):
    h = hashlib.sha256()
    with path.open('rb') as f:
        for chunk in iter(lambda: f.read(1024 * 1024), b''):
            h.update(chunk)
    return h.hexdigest()

count = 0
with outfile.open('w', encoding='utf-8') as out:
    for p in sorted(target.rglob('*')):
        if not p.is_file():
            continue
        if p.suffix.lower() not in media_exts:
            continue
        try:
            digest = sha256_file(p)
        except Exception:
            continue
        out.write(f"{digest}\t{p}\n")
        count += 1
print(f"indexed_target_files={count}")
PY

log "Building import plan"
python3 - "$INCOMING_INDEX" "$TARGET_INDEX" "$IMPORT_PLAN" "$DEST_ROOT" "$ORGANIZE_BY_DATE" <<'PY'
import subprocess
import sys
from pathlib import Path

incoming_index = Path(sys.argv[1])
target_index = Path(sys.argv[2])
plan_path = Path(sys.argv[3])
dest_root = Path(sys.argv[4])
organize_by_date = sys.argv[5] == '1'

existing = set()
for line in target_index.read_text(encoding='utf-8').splitlines():
    if not line.strip():
        continue
    digest, _ = line.split('\t', 1)
    existing.add(digest)

def sane_year(y: str):
    try:
        yi = int(y)
        return 1990 <= yi <= 2035
    except Exception:
        return False

planned = 0
skipped_existing = 0

with plan_path.open('w', encoding='utf-8') as out:
    for line in incoming_index.read_text(encoding='utf-8').splitlines():
        if not line.strip():
            continue
        digest, src = line.split('\t', 1)
        src_path = Path(src)
        if digest in existing:
            skipped_existing += 1
            continue

        dest = None
        if organize_by_date:
            try:
                result = subprocess.run(
                    ['exiftool', '-s3', '-d', '%Y\t%m', '-DateTimeOriginal', '-CreateDate', '-MediaCreateDate', '-TrackCreateDate', str(src_path)],
                    capture_output=True, text=True, check=False
                )
                raw = result.stdout.strip().splitlines()
                y = m = None
                for row in raw:
                    parts = row.split('\t')
                    if len(parts) >= 2 and sane_year(parts[0]) and parts[1].isdigit() and 1 <= int(parts[1]) <= 12:
                        y, m = parts[0], parts[1].zfill(2)
                        break
                if y and m:
                    dest = dest_root / y / m / src_path.name
            except Exception:
                pass

        if dest is None:
            sub = 'raw' if not organize_by_date else 'undated'
            dest = dest_root / sub / src_path.name

        out.write(f"{src_path}\t{dest}\n")
        planned += 1

print(f"planned_imports={planned} skipped_existing={skipped_existing}")
PY

PLANNED=$(wc -l < "$IMPORT_PLAN" | tr -d ' ')
log "Planned imports: $PLANNED"

if [[ $DRY_RUN -eq 1 ]]; then
  log "Dry run enabled - not copying into target"
else
  log "Copying survivors into target"
  while IFS=$'\t' read -r src dest; do
    [[ -n "$src" && -n "$dest" ]] || continue
    mkdir -p "$(dirname "$dest")"
    if [[ -e "$dest" ]]; then
      base="${dest%.*}"
      ext="${dest##*.}"
      if [[ "$base" == "$dest" ]]; then
        ext=""
      else
        ext=".$ext"
      fi
      i=1
      while [[ -e "${base}__dup${i}${ext}" ]]; do
        ((i++))
      done
      dest="${base}__dup${i}${ext}"
    fi
    cp -p "$src" "$dest"
  done < "$IMPORT_PLAN"
fi

log "Writing report: $REPORT_JSON"
python3 - "$IMPORT_PLAN" "$REPORT_JSON" "$SOURCE_DIR" "$TARGET_DIR" "$DEST_ROOT" "$DRY_RUN" <<'PY'
import json
import sys
from pathlib import Path
plan = Path(sys.argv[1])
out = Path(sys.argv[2])
source_dir, target_dir, dest_root, dry_run = sys.argv[3], sys.argv[4], sys.argv[5], sys.argv[6] == '1'
rows = plan.read_text(encoding='utf-8').splitlines() if plan.exists() else []
report = {
    'source_dir': source_dir,
    'target_dir': target_dir,
    'dest_root': dest_root,
    'dry_run': dry_run,
    'planned_imports': len(rows),
    'examples': rows[:20],
}
out.write_text(json.dumps(report, indent=2), encoding='utf-8')
PY

log "Done"
log "Imported files are under: $DEST_ROOT"
log "Delete that subtree later if you want to purge this Takeout import attempt"

## What the script does not do

A few things are intentionally out of scope:

**Near-duplicate cleanup.** Same photo re-exported at lower quality, or processed by WhatsApp before you shared it, or a burst shot you kept three versions of — exact hash comparison won't catch any of that. That's a second pass with Czkawka or similar, done manually after the initial import settles.

**Google album structure.** Takeout exports albums as folder names. The script doesn't try to reconstruct them. Synology Photos can build its own albums on top of a date-organized tree. Chasing Google's album semantics into a different system is more work than it's worth.

**Google's edited versions.** If you edited a photo in Google Photos, Takeout sometimes exports both the original and the edited version. The script imports both if their hashes differ. You can sort that out after the fact.

**Realtime index management.** Synology Photos will start indexing whatever lands in `/photo`. I'm not trying to suppress that — the DS1522+ can handle it.
