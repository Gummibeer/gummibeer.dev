You have a tabletop RPG campaign running in a world-building app. Characters, locations, factions, items — hundreds of entries, all living in someone else's database, behind someone else's API, with no export button in sight. You want them in version-controlled markdown files that you can grep, diff, and drop into Obsidian or a static site.

Laravel Zero is the fastest way to make that happen. It's Laravel stripped down to a console binary: no HTTP kernel, no sessions, no web routes. Just commands, the service container, and everything else you already know.

I built a small tool called Archivist that does exactly this. It speaks to a world-building app's REST API, paginates through every entity type, transforms the JSON into Notion-flavored markdown, and writes files. This post walks through how it's built.

## Project Setup

If you've done this before with a Telegram newsletter command or a data migration script, the setup will feel familiar. Laravel Zero scaffolds in about thirty seconds:

```bash
composer create-project --prefer-dist laravel-zero/laravel-zero archivist
cd archivist
php archivist app:install http  # Illuminate HTTP client
```

The HTTP component is optional but I always install it — it gives you the same fluent client you'd use in a full Laravel app, with retry support and response casting.

Rename the binary in `config/app.php` and you're done:

```php
'name' => 'archivist',
```

Generate the command:

```bash
php archivist make:command ExportCampaign
```

## The Command Structure

The command handles one campaign at a time. It takes an optional campaign ID argument — if you omit it, it fetches the list and asks you to pick.

```php
<?php

namespace App\Commands;

use Illuminate\Support\Facades\Http;
use LaravelZero\Framework\Commands\Command;

class ExportCampaign extends Command
{
    protected $signature = 'export:campaign
        {campaign? : Campaign ID to export}
        {--output= : Output directory (defaults to ./export)}
        {--stdout : Write markdown to stdout instead of files}';

    protected $description = 'Export a campaign from the API to markdown files';

    public function handle(): int
    {
        $campaignId = $this->argument('campaign') ?? $this->pickCampaign();

        if ($campaignId === null) {
            $this->error('No campaign selected.');
            return self::FAILURE;
        }

        $outputDir = $this->option('output') ?? './export/' . $campaignId;

        $this->exportEntities($campaignId, 'characters', $outputDir);
        $this->exportEntities($campaignId, 'locations', $outputDir);
        $this->exportEntities($campaignId, 'items', $outputDir);

        $this->info('Export complete.');
        return self::SUCCESS;
    }
}
```

## Picking a Campaign Interactively

When you don't pass a campaign ID, the command fetches your campaign list and renders a choice question. Laravel Zero ships with Symfony Console's choice helpers, and the `choice()` method wraps them nicely:

```php
private function pickCampaign(): ?string
{
    $this->info('Fetching campaigns...');

    $campaigns = $this->fetchAll('/campaigns');

    if ($campaigns->isEmpty()) {
        $this->warn('No campaigns found.');
        return null;
    }

    $labels = $campaigns->pluck('name', 'id')->all();

    $chosen = $this->choice(
        question: 'Which campaign do you want to export?',
        choices: array_values($labels),
    );

    return array_search($chosen, $labels, strict: true);
}
```

The `choice()` method handles the rendering and input. You get a numbered list, the user types a number or the label, and you get the value back. Zero friction.

## Pagination

The API uses cursor-based pagination — the response includes a `next_page_url` field when there's more data. Some endpoints use page numbers instead. I wrote a `fetchAll()` helper that handles both:

```php
private function fetchAll(string $endpoint, array $query = []): \Illuminate\Support\Collection
{
    $results = collect();
    $url = config('services.archivist.base_url') . $endpoint;

    do {
        $response = Http::withToken(config('services.archivist.token'))
            ->retry(3, 500)
            ->get($url, $query);

        if ($response->failed()) {
            $this->handleRateLimit($response);
            continue;
        }

        $page = $response->json();
        $results->push(...($page['data'] ?? []));

        $url = $page['links']['next'] ?? null;
        $query = []; // don't re-append query params once we have a cursor URL
    } while ($url !== null);

    return $results;
}
```

A few things worth noting. The `retry(3, 500)` on the HTTP client handles transient failures — three attempts, 500ms apart. The `$query = []` line is important: once you follow a cursor URL, the cursor itself is embedded in the URL, so you stop passing your original query params or you'll confuse the server.

For endpoints that paginate by page number instead:

```php
private function fetchPaged(string $endpoint, array $query = []): \Illuminate\Support\Collection
{
    $results = collect();
    $page = 1;

    do {
        $response = Http::withToken(config('services.archivist.token'))
            ->retry(3, 500)
            ->get(config('services.archivist.base_url') . $endpoint, [
                ...$query,
                'page' => $page,
            ]);

        $body = $response->json();
        $results->push(...($body['data'] ?? []));

        $lastPage = $body['meta']['last_page'] ?? 1;
        $page++;
    } while ($page <= $lastPage);

    return $results;
}
```

Same shape, different mechanism. I keep both because different endpoints on the same API use different pagination schemes. This happens more than you'd think.

## Rate Limit Handling

The API rate-limits at 30 requests per minute and returns `429` with a `Retry-After` header. The `handleRateLimit()` helper reads the header, prints a friendly message, and sleeps:

```php
private function handleRateLimit(\Illuminate\Http\Client\Response $response): void
{
    if ($response->status() !== 429) {
        $response->throw();
    }

    $retryAfter = (int) ($response->header('Retry-After') ?: 60);

    $this->warn("Rate limited. Waiting {$retryAfter}s before retrying...");

    sleep($retryAfter);
}
```

If the API doesn't send `Retry-After`, I default to sixty seconds — aggressive enough to be safe, not so long that you're sitting there forever. For APIs that use exponential backoff signals in their response body, you'd read from `$response->json('retry_after')` instead.

## Exporting Entities with a Progress Bar

This is the core loop. For each entity type, we fetch the full list, fire up a progress bar, and write one file per entity:

```php
private function exportEntities(string $campaignId, string $type, string $outputDir): void
{
    $this->info("Exporting {$type}...");

    $entities = $this->fetchAll("/campaigns/{$campaignId}/{$type}");

    if ($entities->isEmpty()) {
        $this->line("  No {$type} found.");
        return;
    }

    $bar = $this->output->createProgressBar($entities->count());
    $bar->start();

    foreach ($entities as $stub) {
        // Fetch the full entity — list endpoints often return stubs
        $entity = Http::withToken(config('services.archivist.token'))
            ->retry(3, 500)
            ->get(config('services.archivist.base_url') . "/campaigns/{$campaignId}/{$type}/{$stub['id']}")
            ->json('data');

        $markdown = $this->toMarkdown($type, $entity);

        $this->writeOutput($markdown, $outputDir, $type, $entity);

        $bar->advance();
    }

    $bar->finish();
    $this->newLine();
}
```

The `createProgressBar()` call comes from Symfony Console via Laravel Zero's `$this->output`. It renders a clean ASCII bar in the terminal. Nothing fancy — it just tells you the tool is still alive, which matters when you have three hundred locations to fetch.

## Transforming JSON to Markdown

Each entity type gets its own transformation. Characters are more complex than items; locations have child locations. I use a simple `match` on the type and delegate to typed methods:

```php
private function toMarkdown(string $type, array $entity): string
{
    return match ($type) {
        'characters' => $this->characterToMarkdown($entity),
        'locations'  => $this->locationToMarkdown($entity),
        'items'      => $this->itemToMarkdown($entity),
        default      => $this->genericToMarkdown($entity),
    };
}

private function characterToMarkdown(array $entity): string
{
    $tags = collect($entity['tags'] ?? [])->pluck('name')->join(', ');

    $lines = [
        "# {$entity['name']}",
        '',
        "**Type:** {$entity['type']}",
        "**Age:** {$entity['age']}",
        "**Tags:** {$tags}",
        '',
        '## Description',
        '',
        strip_tags($entity['entry'] ?? '_No description._'),
    ];

    if (!empty($entity['traits'])) {
        $lines[] = '';
        $lines[] = '## Traits';
        $lines[] = '';
        foreach ($entity['traits'] as $trait) {
            $lines[] = "- **{$trait['name']}:** {$trait['value']}";
        }
    }

    return implode("\n", $lines);
}
```

The world-building app stores rich text as HTML. `strip_tags()` is a blunt instrument but it gets the job done for a personal export tool. If you care about preserving bold and italic, swap in an HTML-to-Markdown converter — `league/html-to-markdown` works well with Laravel Zero.

## Writing Output: File, Stdout, or Both

The `--stdout` flag lets you pipe the output somewhere else. The `--output` flag sets the directory. Both can be active at once, which is useful for debugging a single entity without writing files:

```php
private function writeOutput(string $markdown, string $outputDir, string $type, array $entity): void
{
    if ($this->option('stdout')) {
        $this->line($markdown);
        $this->line('---');
    }

    if (!$this->option('stdout') || $this->option('output')) {
        $dir = "{$outputDir}/{$type}";

        if (!is_dir($dir)) {
            mkdir($dir, 0755, recursive: true);
        }

        $slug = str($entity['name'])->slug()->value();
        $filename = "{$dir}/{$entity['id']}-{$slug}.md";

        file_put_contents($filename, $markdown);
    }
}
```

Running `php archivist export:campaign --stdout 2>/dev/null | head -50` gives you a quick preview of what the markdown looks like before committing to a full export. Small thing, saves you from writing four hundred files to figure out you have an encoding bug.

## The Result

Run it once, get a directory tree:

```
export/
  42/
    characters/
      1-aldric-the-grey.md
      2-mira-stone.md
      ...
    locations/
      1-ironhaven.md
      ...
    items/
      1-the-compass-of-lost-roads.md
      ...
```

Put that in a git repo. Now your campaign has a history. You can `git diff` between sessions, `grep` for every location Mira has visited, or dump the whole thing into a static site.

The whole tool is under five hundred lines. Laravel Zero handles the scaffolding, the service container wires up the HTTP client, and you write the domain logic — pagination, transformation, output. That's the right separation.

If you've already built something similar for a different data source — a Telegram newsletter batch, a CMS migration, an analytics export — the patterns here are identical. Different API, different markdown shape, same command skeleton. That reusability is what makes Laravel Zero worth reaching for when the job is "talk to an API and produce files." It's boring in the best sense: no surprises, no framework overhead, just PHP doing what PHP is good at.
